## Langues de la série 2.15

Français, anglais, allemand, espagnol et finnois pour les textes standards.
Le choix de langue de la borne, celui de l’administration et celui de
WordPress sont distincts. Les textes saisis par le FabLab restent tels quels ;
aucun service de traduction externe n’est utilisé.

# Cinq langues en 2.15.0

FR/EN/DE/ES/FI utilisent les catalogues locaux, formats de dates/nombres adaptés et préférences séparées pour borne/administration. Noms et contenus personnalisés inchangés ; aucune traduction distante. Les brouillons hors ligne ont été contrôlés et les termes critiques corrigés, sans certification par locuteur natif.

# Internationalisation de l’interface

La source native est française. Les catalogues JSON sous `translations/en`
contiennent les équivalents anglais ; les correctifs terminologiques relus sont
séparés du catalogue général. Le plugin utilise une ressource locale équivalente.
Aucun modèle de traduction, téléchargement ou appel à une API n’est nécessaire
dans une installation distribuée.

`i18n.py` marque les textes littéraux des templates à la compilation et les libellés
serveur explicitement natifs. Les scripts traduisent leurs seuls textes d’interface.
Il n’y a pas de remplacement global du HTML rendu, du DOM ou des réponses JSON.

Les valeurs de formulaires, clés, identifiants, statuts, URL et données enregistrées
restent indépendants de la langue. Les objets de libellés gardent leur valeur native
dans les traitements ; seule leur présentation ou leur projection UI est traduite.
Les colonnes personnalisées et contenus de structure ne passent pas dans le catalogue.

Pour ajouter une langue, créer un catalogue distinct, déclarer le code de langue
dans le registre des choix de `i18n.py`, puis adapter les choix autorisés des réglages
et les ressources locales WordPress. Ne pas modifier les clés métier.
Ajouter les tests de messages, valeurs POST, échappement HTML, attributs accessibles,
formulaires, navigateurs et indépendance des sessions correspondants.

Pour maintenir une traduction : relire le contexte d’origine, conserver toutes les
variables `{0}`, `{1}`, les unités, bornes et instructions sensibles. Les mots de
confirmation comme `SUPPRIMER` ne doivent pas être traduits. Ne pas créer une
traduction d’un nom ou d’une catégorie configurée par une structure.

Les outils de préparation linguistique sont réservés au développement. Le résultat
nécessite une relecture ; un nombre de clés ou une validation de syntaxe ne suffit
pas à attester la qualité d’une interface dans les deux langues.
